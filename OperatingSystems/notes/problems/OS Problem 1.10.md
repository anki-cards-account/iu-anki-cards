### Ответ
<div class="lang-pair"><label class="lang-btn"><input class="lang-sw" type="checkbox"><span class="is-ru">ru</span><span class="is-en">en</span></label><div class="lang-ru"><p><b>Kernel mode</b> — бит в процессоре (часто PSW): разрешены любые инструкции и любой адрес, включая I/O. Здесь живёт ядро. Crash валит весь PC: ловить «ниже» некому.</p><p><b>User mode</b> — только subset инструкций. I/O и управление машиной железо <i>само</i> режет. Crash процесса recoverable: ядро живо.</p><p><b>Зачем два режима:</b> приложениям нельзя давать полный ключ, иначе вкладка браузера сотрёт таблицы ОС. Ядро остаётся trusted, переход только через <a class="internal-link" data-href="System call" href="System call">System call</a> (TRAP). Без TRAP два режима бессмысленны: из user mode нечем легально попросить диск.</p><p>Атомы: <a class="internal-link" data-href="Kernel mode" href="Kernel mode">Kernel mode</a>, <a class="internal-link" data-href="User mode" href="User mode">User mode</a>.</p></div><div class="lang-en"><p><b>Kernel mode</b> — a CPU bit (often in the PSW): any instruction, any address, including I/O. The kernel runs here. A crash takes down the whole PC: nothing sits “below” to catch it.</p><p><b>User mode</b> — only a subset of instructions. I/O and machine control are refused by the hardware itself. A process crash is recoverable: the kernel is still up.</p><p><b>Why two modes:</b> applications must not get the full key, or a browser tab could wipe OS tables. The kernel stays trusted; the only entry is a <a class="internal-link" data-href="System call" href="System call">System call</a> (TRAP). Without TRAP the two modes are useless: user mode has no legal way to ask for the disk.</p><p>See <a class="internal-link" data-href="Kernel mode" href="Kernel mode">Kernel mode</a>, <a class="internal-link" data-href="User mode" href="User mode">User mode</a>.</p></div></div>
