**Мини-словарь:**
- physical CPU — настоящий пакет с конвейером и кэшем. В задаче их **два**.
- hyperthreading (HT) / logical processor — второй поток на **том же** физическом CPU: кажется «ещё одним ядром», но ALU/кэш общие. 2 CPU × 2 threads = 4 logical, всё ещё **2** физических.
- CPU-bound — программа не уходит в I/O, только крутит CPU. Тогда делёж HT почти не прячется за ожиданием диска.
- «не меняют CPU once assigned» — после посадки программа **не мигрирует** на другой пакет. Время = насколько перегрузили самый загруженный **физический** CPU.

Milestone: [[OS Tutorial 1 - введение]]
Problem: [[OS Problem 1.13]]

### Концепт

Интуитивная ловушка: «4 logical ⇒ 4 независимых гонщика». Нет: два logical на одном пакете **делят один** физический CPU. HT — не [[Multicore]] (там полные ядра, true parallelism). HT ближе к [[Multithreading]].

Поэтому ответ задачи — **диапазон**, не одно число: scheduler решает, кто с кем сидит на одном пакете. Лучший случай ~20 msec (длинная $P2=20$ одна на пакете), худший ~35, если всех троих запихнули на один пакет.

### Под капотом

Дано: 2 CPU, на каждом 2 threads. $P0,P1,P2$ = $5$, $10$, $20$ msec. Все 100% CPU-bound, не блокируются, CPU не меняют.

Время завершения = максимум по двум **физическим** CPU (кто сколько на него посадили; HT на одном пакете не даёт «20+20 за 20»).

Случаи туториала:

| Назначение | Итог (msec) | Почему |
|---|---|---|
| $P0$+$P1$ на одном CPU, $P2$ на другом | **20** | длинная работа 20 идёт одна; 5+10 ≤ 20 |
| $P0$+$P2$ вместе, $P1$ отдельно | **25** | пакет с 5+20 |
| $P1$+$P2$ вместе, $P0$ отдельно | **30** | пакет с 10+20 |
| все три на одном CPU | до **35** | 5+10+20, если на одном logical подряд |

Экзамен: назвать **20…35 msec** и сказать, что число зависит от placement; HT ≠ четыре полноценных ядра.
