**Мини-словарь:**
- kernel mode (supervisor mode) — режим **процессора**: разрешены любые инструкции и любой адрес памяти, включая I/O и смену режима. Здесь работает ядро ОС.
- privileged instruction — инструкция, которую CPU **откажется** выполнить в [[User mode]] (ввод-вывод, управление MMU, halt, …).
- crash в kernel mode — падает **вся машина**: нет слоя «ниже», который бы это отловил.

Milestone: [[OS Lection 1 - введение]], [[OS Tutorial 1 - введение]]
Problem: [[OS Problem 1.10]]

### Концепт

Режим — это не «папка на диске», а **бит в процессоре** (часто в PSW). Пока бит = kernel, код может трогать диск и чужую память. Пока bit = user — железо само режет такие попытки.

Зачем так проектировать ОС: приложениям нельзя давать полный ключ. Иначе одна вкладка браузера стирает ядро. Ядро оставляют в kernel mode, всё остальное — в user mode, переход только через [[System call]].

### Под капотом

Большинство компьютеров в курсе имеют **два режима**: kernel и [[User mode]].

ОС в kernel mode:

- **полный доступ ко всему hardware**;
- **любая** инструкция, **любой** адрес памяти.

Это место самых доверенных функций. **Crash здесь катастрофичен** — останавливает весь PC.

Драйверы поэтому живут в ядре ([[Device driver]]). Пользовательская программа не прыгает в эти адреса сама: только TRAP / [[System call]].
