**Мини-словарь:**
- resource manager — ОС как распределитель процессоров, памяти и I/O между программами.
- bottom-up — взгляд **от железа вверх к программам**: внизу мало CPU/RAM/устройств, наверху много желающих.
- allocation — упорядоченная и контролируемая выдача ресурса, не «кто первый встал».

Milestone: [[OS Lection 1 - введение]], [[OS Tutorial 1 - введение]]
Problem: [[OS Problem 1.1]]

### Концепт

«Снизу вверх» — снова не этаж в корпусе. Ось такая:

1. внизу — конечные куски железа (один CPU, N гигабайт RAM, один диск);
2. наверху — много программ, которым это всё нужно сразу.

ОС смотрит **с железа** и решает: кому сейчас тик CPU, какой кусок памяти, кто пишет на диск. Не «дать всем всё», а **orderly and controlled allocation**. Иначе две программы перетирают память друг друга.

Противоположный взгляд — [[Extended Machine]] (сверху вниз: удобный API над железом).

### Под капотом

ОС должна **управлять всеми кусками** сложной системы. Job: обеспечить **orderly and controlled allocation** процессоров, memories и I/O devices среди программ, которые их хотят.

Это вторая роль [[Operating System]] (экзамен: *resource management*). Как именно делят один ресурс между многими — [[Multiplexing]] (время vs пространство: CPU по очереди vs диск нарезанный на куски).
