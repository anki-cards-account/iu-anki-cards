**Мини-словарь:**
- extended machine — ОС как «улучшенный процессор»: программа думает, что работает с простыми объектами (файл, блок диска), а не с регистрами контроллера.
- top-down — взгляд **от приложения вниз к железу**: начинаешь с удобного API и прячешь детали hardware.
- disk driver — типичная абстракция: вместо «адского» интерфейса диска — read/write блоков.

Milestone: [[OS Lection 1 - введение]], [[OS Tutorial 1 - введение]]

### Концепт

«Сверху вниз» здесь **не** про то, что ОС стоит физически выше процессора. Это про **направление проектирования**:

1. наверху — программист и его программа («хочу прочитать блок 17»);
2. внизу — капризное разное железо (команды контроллера, порты, тайминги).

ОС стоит между ними и говорит: «для тебя диск — массив блоков». Сама она уже дерётся с контроллером. Отсюда имя **extended machine**: к «голому» CPU как будто добавили понятные инструкции/объекты.

Противоположный взгляд — [[Resource Manager]] (снизу вверх: железо дефицитно, программ много).

### Под капотом

**Проблема:** hardware сложный и даёт software developers трудные и **несогласованные** интерфейсы (у диска, сети, таймера — разные протоколы).

**Решение:** абстракции. Пример — disk driver: работает с железом и даёт интерфейс **читать и писать disk blocks**. Программа не программирует контроллер.

Это одна из двух ролей [[Operating System]] (экзамен: *fine abstractions from the bare metal*). Драйвер при этом должен быть в ядре, см. [[Device driver]].
