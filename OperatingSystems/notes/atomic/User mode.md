**Мини-словарь:**
- user mode — режим, в котором работает «остальное» ПО: доступен только subset инструкций.
- system call (TRAP) — ловушка в ядро: программа просит услугу ОС.

Milestone: [[OS Lection 1 - введение]], [[OS Tutorial 1 - введение]]
Problem: [[Problem 1.10]]

### Концепт

Пользовательский код намеренно **ограничен**: нельзя самому крутить диск или менять режим CPU. Нужен диск — зови ОС. Это не из вредности, а чтобы одна программа не уничтожила ресурсы остальных ([[Resource Manager]]).

### Под капотом

Всё ПО кроме ОС работает в user mode:

- доступен **только subset** машинных инструкций;
- инструкции, которые **влияют на управление машиной** или делают **I/O**, пользовательским программам **запрещены**;
- код **не может напрямую** ходить в hardware или в произвольную память — только через system APIs / [[System call]].

Crash в user mode **всегда recoverable** (изоляция от ядра). Зачем два режима при дизайне ОС: защита; ошибка приложения не валит машину, в отличие от [[Kernel mode]].

Чтобы получить сервис ОС, программа делает **system call (TRAP)** → CPU в kernel mode → ОС → возврат. Без TRAP privileged-операция железом запрещена.
