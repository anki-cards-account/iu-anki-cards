**Мини-словарь:**
- user mode — режим процессора для «всего остального» ПО: доступен только **subset** инструкций. I/O и управление машиной запрещены железом, не «вежливостью» библиотеки.
- recoverable crash — упал процесс, ядро живо, можно убить процесс и жить дальше. Противоположность crash в [[Kernel mode]].
- system call (TRAP) — единственный легальный вход из user mode в ядро.

Milestone: [[OS Lection 1 - введение]], [[OS Tutorial 1 - введение]]
Problem: [[OS Problem 1.10]]

### Концепт

Ограничения user mode — не вредность API, а **изоляция для [[Resource Manager]]**. Если бы Word сам писал на диск как хочет, он мог бы затереть чужие файлы и таблицы ядра.

Нужен диск — не «вызвать контроллер», а попросить ОС. Процессор сам не даст IN/OUT из user mode.

### Под капотом

Всё ПО кроме ОС работает в user mode:

- только **subset** машинных инструкций;
- инструкции, которые **влияют на управление машиной** или делают **I/O**, запрещены;
- нет прямого хода в hardware и в произвольную память — только system APIs / [[System call]].

Crash в user mode **всегда recoverable** (изоляция от ядра). Зачем два режима при дизайне ОС: ошибка приложения не валит машину; ядро остаётся TCB (trusted). Без TRAP privileged-операция железом просто не исполняется.
