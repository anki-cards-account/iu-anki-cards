**Мини-словарь:**
- system call — запрос услуги у ОС из user-программы (`read`, `write`, создать процесс, …). Это не обычный `call` в соседнюю функцию того же режима.
- TRAP — ловушка процессора: исполнение прыгает в заранее заданную точку **ядра**, CPU переключает режим в [[Kernel mode]].
- return from trap — ОС закончила, режим снова user, программа продолжает как ни в чём не бывало (или получает код ошибки).

Milestone: [[OS Lection 1 - введение]], [[OS Tutorial 1 - введение]]
Problem: [[OS Problem 1.10]]

### Концепт

Дверь в ядро должна быть **узкой и с рамкой металлоискателя**. Если дать программе адрес ядра и сказать «прыгай», она испортит таблицы. TRAP — это «нажми кнопку звонка»: железо само меняет режим и отдаёт управление только входной точке ОС.

Поэтому два режима без system call бессмысленны: из user mode просто нечем легально попросить I/O.

### Под капотом

Из [[User mode]] программа **не имеет** права выполнять I/O и управляющие инструкции. Путь к сервису ОС:

1. программа делает **system call (TRAP)**;
2. hardware делает trap **в ядро**;
3. CPU оказывается в [[Kernel mode]];
4. вызывается ОС, выполняет запрос, возвращает управление.

На экзамене: system call = способ получить услугу ОС, **не нарушая** границу режимов. Связка с [[Kernel mode]] / [[User mode]]: режимы — замок, TRAP — ключ, который выдаёт только железо.
