**Мини-словарь:**
- controller — часть устройства: принимает команды ОС и выполняет их.
- device driver — ПО, которое говорит с контроллером (команды и ответы); должно быть **в ОС**, чтобы бежать в kernel mode.
- I/O port space — совокупность всех device registers.
- memory-mapped I/O — регистры устройства отображены в адресное пространство ОС и читаются/пишутся как ordinary memory words.

Milestone: [[OS Lection 1 - введение]]

### Концепт

Устройство = тупой механизм + умный контроллер. Драйвер — переводчик ОС↔контроллер. Он не может жить в user-программе: нужны privileged IN/OUT или доступ к регистрам.

### Под капотом

I/O device обычно из **двух частей**:

1. **controller** — принимает команды ОС и исполняет;
2. **device itself** — простой и стандартный интерфейс (мало умеет → легче стандартизировать).

**Device driver** говорит с контроллером. Его **надо положить в ОС**, чтобы он работал в [[Kernel mode]].

У каждого контроллера — небольшой набор **registers**. Все они вместе = **I/O port space**.

Два способа достучаться до регистров:

- регистры **mapped** в address space ОС → read/write как обычные memory words;
- регистры в **special I/O port space**, у каждого свой port address → специальные инструкции **IN и OUT** (только kernel mode).

Как гонять данные: [[IO transfer]] (busy waiting, interrupt, DMA). Назначение номеров прерываний картам: [[Bus]] (Plug and Play).
